# گزارش آمار و عملکرد

مسیر صفحه: `/admin/analytics`؛ بازه‌ها: `?days=7` و `?days=30`. صفحه، سرویس و Server Action تازه‌سازی همگی دسترسی فعلی ادمین را سمت سرور بررسی می‌کنند. مسیر API عمومی جدیدی اضافه نشده است. منوی مدیریت دسکتاپ و موبایل از همان ناوبری مشترک استفاده می‌کنند.

## تنظیمات و رفتار

| تنظیم روی سرویس رانفلر | مقدار یا اقدام لازم |
| --- | --- |
| `GA4_PROPERTY_ID` | دقیقاً `563535207`؛ شناسهٔ Property، نه شناسهٔ اندازه‌گیری با پیشوند `G-` |
| `GOOGLE_CLIENT_EMAIL` | مقدار محرمانهٔ موجود حفظ شود؛ فقط وجود آن در محیط اجرای برنامه بررسی شود |
| `GOOGLE_PRIVATE_KEY` | مقدار محرمانهٔ موجود حفظ شود؛ newline واقعی و `\n` هر دو پشتیبانی می‌شوند |
| دسترسی گوگل | فعال بودن Google Analytics Data API و نقش Viewer حساب سرویس روی همین Property بررسی شود |
| دسترسی MongoDB | حساب موجود برنامه مجوز خواندن و نوشتن مجموعهٔ `analyticscaches` داشته باشد؛ تغییر مدل‌های فروشگاه یا seed لازم نیست |

هیچ‌کدام از این دو اعتبارنامهٔ گوگل نباید در فایل مخزن، خروجی build، لاگ، توضیح Pull Request یا متغیر دارای پیشوند `NEXT_PUBLIC_` قرار بگیرد. تنظیمات موجود `MONGODB_URI`، `AUTH_SECRET`، `AUTH_URL` و نشانی سایت حفظ شوند.

متغیرهای صرفاً سمت سرور در `.env.example` مستند شده‌اند: `GA4_PROPERTY_ID=563535207`، `GOOGLE_CLIENT_EMAIL` و `GOOGLE_PRIVATE_KEY`. دو مقدار محرمانه باید در تنظیمات رانفلر باقی بمانند؛ در مخزن، مرورگر و گزارش خطا قرار نمی‌گیرند. کلید خصوصی با newline واقعی و `\n` پشتیبانی می‌شود. نبودن یا نامعتبر بودن این تنظیمات فقط گزارش آمار را غیرفعال می‌کند و build را خراب نمی‌کند. ساخت کلاینت و تماس با گوگل فقط هنگام درخواست مجاز گزارش انجام می‌شود.

SDK رسمی `@google-analytics/data` و `BetaAnalyticsDataClient.runReport` استفاده می‌شوند. معیارها `activeUsers`، `newUsers`، `screenPageViews` و `sessions`؛ ابعاد `date`، `sessionSourceMedium` و `pagePath` هستند. یک درخواست سبک، منطقه زمانی Property را از `metadata.timeZone` می‌گیرد؛ پنج گزارش برای مجموع بازه فعلی، مجموع بازه قبلی، روزانه، شش منبع برتر و ده صفحه پربازدید به‌صورت موازی دریافت می‌شوند. هر درخواست timeout دوازده‌ثانیه‌ای دارد و تکرار خودکار SDK خاموش است.

بازه‌ها شامل هفت یا سی روز کامل تا پایان دیروز بر اساس منطقه زمانی Property هستند؛ بازه قبلی هم‌اندازه، مجاور و بدون هم‌پوشانی است. کاربران کل بازه از گزارش بدون بُعد روزانه گرفته می‌شوند. مقدار قبلی صفر، درصد تغییر ندارد. منابع ورود تعداد نشست هستند؛ منابع برتر به‌عنوان کل منابع یا جمع کامل نشست‌ها معرفی نمی‌شوند. مسیر `/products/[slug]` با عنوان «صفحات محصول (تجمیعی)» نشان داده می‌شود؛ نام یا آمار محصول جداگانه تولید نمی‌شود.

زمان «آخرین دریافت گزارش» پایان دریافت موفق از گوگل است و به وقت تهران نمایش داده می‌شود؛ زمان هر بازدید یا زمان آخرین پردازش گوگل نیست. Data API زمان قطعی تکمیل داده‌ها را در این گزارش ارائه نمی‌کند. تاریخ بازه و روزهای نمودار، برچسب تقویمی Property هستند؛ نمایش شمسی آنها روز را به منطقه زمانی مرورگر تبدیل نمی‌کند. تأخیر پردازش گوگل و محدودیت‌های نمونه‌گیری، آستانه و تجمیع احتمالی در صفحه توضیح داده می‌شوند.

کش `AnalyticsCache` در MongoDB برای هر Property و بازه جداست و گزارش موفق را پانزده دقیقه نگه می‌دارد. خطای پاک‌سازی‌شده شصت ثانیه کش می‌شود. قفل اتمیک مشترک مانع دریافت هم‌زمان گزارش‌ها می‌شود و تازه‌سازی دستی حداقل شصت ثانیه فاصله دارد؛ قفل درخواست پس از نود ثانیه منقضی می‌شود تا crash سرور آن را دائمی نکند. تغییر بازه از محدودیت تازه‌سازی دستی مستقل است. این مجموعه حداکثر دو سند گزارش و یک سند قفل به ازای هر Property استفاده‌شده دارد؛ تاریخ انقضا هنگام خواندن بررسی می‌شود و به TTL پس‌زمینه وابسته نیست. اکانت دیتابیس باید مجوز خواندن و نوشتن این مجموعه را داشته باشد. ذخیره‌سازی ناموفق، تنظیمات ناقص، عدم دسترسی گوگل، خطای ارتباط و سهمیه جدا هستند؛ هیچ‌یک به گزارش صفر تبدیل نمی‌شوند. نبود داده فقط پس از پاسخ موفق گوگل نمایش داده می‌شود.

## انتشار و تأیید اتصال واقعی

نسخهٔ SDK روی شاخهٔ رسمی شش نگه داشته شده تا حداقل Node.js پروژه تغییر نکند؛ شاخهٔ هفت به Node.js 22 نیاز دارد. وابستگی‌های واسط Gaxios و Rimraf با override به نسخه‌های اصلاح‌شده و سازگار به‌روزرسانی شده‌اند. Node.js 24 مطابق راهنمای فعلی پروژه برای اجرای همهٔ ابزارها توصیه می‌شود.

بررسی‌های پروژه: `npm run lint`، `npm run typecheck`، `npm run test` و `npm run build`. آزمون مرورگر پس از build با `npx tsx tests/analytics-browser.mjs` اجرا می‌شود؛ Python با Playwright و مرورگر نصب‌شده لازم است. در صورت نیاز، نام کانال مرورگر را با `LAUNCHO_BROWSER_CHANNEL` (برای نمونه `msedge`) تعیین کنید. اسکریپت، MongoDB موقت و سرور ایزوله ایجاد می‌کند، هرگونه اعتبارنامهٔ گزارش‌گیری محیط میزبان را با مقادیر خالی/آزمایشی جایگزین می‌کند و screenshotها را در `test-results/analytics` می‌گذارد. دادهٔ آزمایشی فقط در این محیط موقت وجود دارد و هیچ گزارش آزمایشی به گوگل ارسال نمی‌شود.

۱. پس از اجازهٔ مالک، تغییرات در شاخه جدا بازبینی و منتشر شوند. در رانفلر فقط شناسهٔ Property را اضافه یا بررسی کنید و حضور دو متغیر محرمانهٔ موجود را بدون چاپ مقدار بررسی کنید؛ هیچ متغیر محرمانه‌ای پیشوند `NEXT_PUBLIC_` نداشته باشد. سرویس را پس از تنظیم متغیرها بازسازی/راه‌اندازی کنید.

۲. با ادمین وارد `/admin/analytics` شوید. منطقه زمانی نشان‌داده‌شده را با تنظیمات Property و بازه کامل تا دیروز تطبیق دهید. کارت‌ها را با همان بازه و معیارها در Google Analytics مقایسه کنید؛ محدودیت گزارش و تأخیر پردازش را لحاظ کنید. مجموع کاربران را با جمع نمودار مقایسه نکنید.

۳. هر دو بازه را باز کنید؛ بارگذاری دوباره در پانزده دقیقه باید زمان دریافت قبلی را نگه دارد. پس از حداقل شصت ثانیه، تازه‌سازی دستی زمان دریافت جدید داشته باشد؛ درخواست سریع بعدی محدود شود. منابع ورود واحد نشست و صفحات محصول عنوان تجمیعی داشته باشند.

۴. در نشست مهمان و مشتری دسترسی صفحه و Server Action مجاز نباشد؛ پس از لغو نقش ادمین نیز نشست قدیمی نباید گزارش بگیرد. Network مرورگر نباید اعتبارنامه یا تماس مستقیم با Data API داشته باشد. اتصال و رویدادهای فعلی GA4 تغییری نکرده‌اند.

۵. برای تطبیق واقعی، در GA4 ابتدا Property با شناسهٔ `563535207` را انتخاب کنید. منطقه زمانی Property و تاریخ شروع/پایان دقیق نمایش‌داده‌شده در صفحه، تا پایان دیروز، یکسان باشد. `Active users`، `New users`، `Views` و `Sessions` را با چهار کارت مقایسه کنید؛ برای منابع ورود از `Session source / medium` و معیار `Sessions` و برای صفحات از `Page path` و `Views` استفاده کنید. بازهٔ قبل نیز دقیقاً همان تعداد روز و بلافاصله قبل از بازهٔ فعلی باشد. مقایسه با Realtime یا جمع کاربران روزانه، تأیید درستی کارت کاربران نیست. زمان دریافت، بازه، منطقه زمانی، اعداد دو طرف و هشدارهای احتمالی نمونه‌گیری/آستانه را برای هر دو بازه ثبت کنید؛ در صورت اختلاف، بررسی را ناموفق یا نیازمند بررسی ثبت کنید، نه تأییدشده.

رهگیری فعلی سایت referrer و اطلاعات کمپین را حذف می‌کند و در این تغییر دست‌نخورده است؛ بنابراین منابع ورود فقط آنچه گوگل واقعاً ذخیره کرده نشان می‌دهند و ممکن است سهم بالایی از ورودی مستقیم داشته باشند. این صفحه دادهٔ از‌دست‌رفتهٔ رهگیری را بازسازی نمی‌کند.

تست‌های محلی از SDK شبیه‌سازی‌شده و دیتابیس موقت استفاده می‌کنند؛ عبور این تست‌ها اثبات دسترسی واقعی حساب سرویس روی رانفلر نیست. تأیید واقعی نیازمند محیطی است که اعتبارنامهٔ تنظیم‌شده و دسترسی شبکه به گوگل دارد.
