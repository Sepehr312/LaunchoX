# لانچ‌اوکس

فروشگاه آنلاین فارسی با Next.js، TypeScript و Tailwind CSS. پروژه مطابق بخش ۱۲ از [مشخصات](docs/SPEC.md) در دوازده مرحله ساخته می‌شود؛ مراحل اول تا سوم (راه‌اندازی، زیرساخت رابط کاربری و اتصال دیتابیس) پیاده‌سازی شده‌اند.

## پیش‌نیازها

- Node.js نسخهٔ 24 LTS و npm (برای سازگاری با ابزارهای جدید)
- Docker Desktop با موتور کانتینرهای Linux برای MongoDB محلی

## راه‌اندازی

```sh
npm install
```

اگر `.env.local` ندارید، `.env.example` را در آن کپی کنید. فایل موجود را بازنویسی نکنید. قبل از مرحلهٔ احراز هویت، مقدار نمونهٔ `AUTH_SECRET` را با یک مقدار تصادفی امن و رمز نمونهٔ ادمین را با رمز شخصی جایگزین کنید.

```sh
npm run db:up
npm run dev
```

صفحهٔ آغازین در <http://localhost:3000> نمایش داده می‌شود. MongoDB نسخهٔ ۷ روی پورت ۲۷۰۱۷ اجرا می‌شود و داده‌های آن در volume نام‌دار `mongo_data` باقی می‌ماند. برای استفاده از Atlas، مقدار `MONGODB_URI` را تغییر دهید. مسیر `/api/health` اتصال واقعی دیتابیس را با ping بررسی می‌کند.

تنظیمات الزامی در `src/lib/env.ts` با Zod بررسی می‌شوند؛ اگر فایل محیطی قدیمی فقط بخشی از کلیدها را دارد، کلیدهای گمشدهٔ `.env.example` را اضافه کنید و مقادیر موجود را حفظ کنید. `AUTH_URL` در production الزامی است و تنظیمات seed در این مرحله اختیاری‌اند. پیام تنظیم نامعتبر نام کلید را نشان می‌دهد و مقدار آن را افشا نمی‌کند.

در PowerShell با محدودیت اجرای اسکریپت، از `npm.cmd` به‌جای `npm` استفاده کنید.

## دستورها

| دستور               | کاربرد                                         |
| ------------------- | ---------------------------------------------- |
| `npm run dev`       | اجرای توسعه با Turbopack                       |
| `npm run build`     | ساخت نسخهٔ production                          |
| `npm start`         | اجرای نسخهٔ ساخته‌شده                          |
| `npm run lint`      | بررسی ESLint                                   |
| `npm run typecheck` | بررسی TypeScript                               |
| `npm run test`      | اجرای Vitest                                   |
| `npm run format`    | فرمت با Prettier و مرتب‌سازی کلاس‌های Tailwind |
| `npm run db:up`     | اجرای MongoDB محلی                             |
| `npm run seed`      | رزروشده برای مرحلهٔ پنجم؛ فعلاً قابل اجرا نیست |

## دادهٔ نمونه

اسکریپت seed در مرحلهٔ پنجم پیاده‌سازی می‌شود. پس از آن، قبل از `npm run dev`، دستور `npm run seed` اجرا خواهد شد. حساب ادمین از `SEED_ADMIN_EMAIL` و `SEED_ADMIN_PASSWORD` ساخته می‌شود. اکنون هیچ حساب یا محصولی ساخته نشده است.

## ساختار فعلی

- `src/app/`: layout فارسی و RTL، توکن‌های روشن/تاریک و صفحهٔ آزمایشی در `/`
- `src/components/ui/`: کامپوننت‌های پایهٔ Button، Input، Card و Badge
- `src/lib/`: ابزارهای فرمت فارسی، slug، ترکیب کلاس‌ها، تنظیمات محیطی، اتصال MongoDB و خطاهای برنامه
- `src/services/health.service.ts`: بررسی وضعیت دیتابیس؛ Route Handler از طریق سرویس به دیتابیس دسترسی دارد
- `src/app/api/health/route.ts`: پاسخ JSON پویا و بدون کش برای وضعیت سلامت
- `tests/`: تست‌های format، slug، env، db، health و errors
- `public/`: تصاویر استاتیک قالب اولیه
- `vitest.config.mts`: تنظیمات تست و مسیر مستعار `@/`
- `docker-compose.yml`: دیتابیس محلی
- `AGENTS.md` و `docs/SPEC.md`: قوانین و مشخصات پروژه

مدل‌ها، سرویس‌های فروشگاه، actionها و اعتبارسنجی فرم‌ها در مراحل مربوط ساخته خواهند شد.

## Decisions

- مرحلهٔ سوم: تنظیمات با `getEnv()` هنگام استفاده در سرور بررسی می‌شوند تا build به اتصال دیتابیس وابسته نباشد؛ تنظیمات seed اختیاری‌اند و در مرحلهٔ seed الزام آن‌ها اعمال خواهد شد.
- برای رعایت قوانین لایه‌ها، health از یک سرویس کوچک استفاده می‌کند. مطابق قرارداد عمومی API در بخش ۸، پاسخ آن `{ data: { status: "ok", db: "up" | "down" } }` با HTTP 200 است؛ `status` سلامت برنامه و `db` وضعیت اتصال را نشان می‌دهد. خطای تنظیمات پاسخ عمومی فارسی با HTTP 500 دارد.
- اتصال اولیهٔ MongoDB حداکثر ۵ ثانیه برای انتخاب سرور منتظر می‌ماند؛ promise مشترک روی `globalThis` نگه داشته می‌شود و پس از شکست اولیه پاک می‌شود تا درخواست بعدی دوباره تلاش کند. اتصال برقرارشده از بازیابی خودکار درایور استفاده می‌کند.
- برای health که Route Handler JSON است، `loading.tsx` و حالت خالی رابط کاربری کاربرد ندارند.

- مرحلهٔ دوم: فقط Button، Input، Card و Badge برای صفحهٔ نمونه لازم‌اند؛ Modal و Pagination در مراحل نیازمند آن‌ها ساخته می‌شوند.
- تاریخ‌ها با منطقهٔ زمانی Asia/Tehran نمایش داده می‌شوند تا نتیجه به منطقهٔ زمانی سرور وابسته نباشد؛ قیمت نامعتبر، منفی یا غیرصحیح با خطای فارسی رد می‌شود.
- slug حروف فارسی را حفظ می‌کند؛ نیم‌فاصله را مانند فاصله و ارقام فارسی/عربی را مانند ارقام انگلیسی در نظر می‌گیرد. عنوان بدون حرف یا رقم به `item` تبدیل می‌شود.
- یکتاسازی slug با `createUniqueSlug(title, exists)` و callback همگام یا ناهمگام انجام می‌شود؛ اتصال دیتابیس ندارد و جایگزین محدودیت یکتایی مدل در مرحلهٔ مربوط نیست.
- صفحهٔ آزمایشی فعلاً در `/` است و ورودی نمونه فقط در مرورگر و با بازنشانی بومی فرم کار می‌کند؛ هیچ داده‌ای در سرور پردازش یا ذخیره نمی‌شود.

- گزینهٔ agentRules در Next.js غیرفعال شد تا اجرای dev محتوای AGENTS.md پروژه را خودکار تغییر ندهد.

- الزام آخرین نسخهٔ پایدار برای TypeScript و ESLint با وابستگی‌های lint ناسازگار شد: typescript-eslint بازهٔ کمتر از 6.1 و eslint-plugin-react نسخهٔ 9 را پشتیبانی می‌کنند. آخرین نسخه‌های سازگار TypeScript 6.0 و ESLint 9 انتخاب شدند تا بررسی‌های اجباری سالم بمانند.

- حداقل Node در package.json طبق سند >=20.19 باقی مانده، اما Vitest 5 به Node ^22.12 یا ^24 یا >=26 نیاز دارد؛ محیط پیشنهادی و بررسی‌شده Node 24 است. این تفاوت ناشی از الزام نصب آخرین نسخهٔ پایدار ابزارهاست.

- برای رعایت تقدم AGENTS.md بر صفحهٔ پیش‌فرض انگلیسی مرحلهٔ اول، متن و metadata فارسی و حداقل RTL و وزیرمتن از همین مرحله اعمال شده‌اند؛ توکن‌های برند، ابزارهای فرمت و کامپوننت‌های پایه متعلق به مرحلهٔ دوم هستند.
- قالب با create-next-app داخل `.scaffold-tmp/launchox` ساخته شد تا نام پکیج معتبر باشد؛ فایل دستورالعمل تولیدشدهٔ قالب جایگزین AGENTS.md پروژه نشد.
- وابستگی‌های هر قابلیت در مرحلهٔ مربوط نصب می‌شوند؛ Vitest و tsx از اکنون برای دستورهای تعریف‌شده آماده‌اند.
- در مرحلهٔ اول Vitest با `passWithNoTests` اجرا می‌شد؛ در مرحلهٔ دوم این گزینه حذف شد و تست‌های واقعی format و slug اجرا می‌شوند.
- اسکریپت seed اکنون فقط در package.json تعریف شده؛ پیاده‌سازی آن مطابق ترتیب سند در مرحلهٔ پنجم خواهد بود.
- Prettier فایل‌های AGENTS.md و docs را نادیده می‌گیرد تا اسناد ورودی دست‌نخورده بمانند.

## توسعه‌های آینده

درگاه پرداخت واقعی، ورود OTP و آپلود تصویر خارج از محدودهٔ فعلی هستند؛ نقاط توسعه در مراحل مشخص‌شدهٔ سند آماده می‌شوند.

## گزارش بررسی مرحلهٔ اول

- `npm run lint`، `npm run typecheck` و `npm run build`: موفق.
- `npm run test`: خروج موفق؛ هنوز تست واحدی وجود ندارد و نخستین تست‌ها در مرحلهٔ دوم اضافه می‌شوند.
- `npm run dev`: صفحهٔ آغازین با پاسخ HTTP 200 نمایش داده شد.
- مرورگر در عرض ۳۶۰ پیکسل: زبان فارسی، جهت RTL، وزیرمتن بارگذاری‌شده و عرض محتوا برابر عرض صفحه، بدون اسکرول افقی.
- `npm run db:up`: موفق؛ پاسخ MongoDB به ping برابر `{ ok: 1 }` بود.
- هش SHA-256 فایل‌های `AGENTS.md` و `docs/SPEC.md` با نسخهٔ اولیه یکسان است؛ `.env.local` حفظ شده و در Git نادیده گرفته می‌شود.
- محیط بررسی: Node.js 24.20.0؛ Next.js 16.3.8، TypeScript 6.0.3، ESLint 9.39.5 و Tailwind CSS 4.3.3.

## گزارش بررسی مرحلهٔ دوم

- layout با `lang="fa"` و `dir="rtl"` و فونت Vazirmatn با subsetهای arabic و latin تأیید شد؛ metadata صفحه فارسی است.
- توکن‌های primary، surface، muted، border، danger و success با Tailwind v4 و حالت تاریک خودکار اضافه شدند.
- ابزارهای `cn`، `formatPrice`، `formatDate`، `toPersianDigits`، `normalizeDigits`، `slugify` و `createUniqueSlug` ساخته شدند.
- چهار کامپوننت Button، Input، Card و Badge و صفحهٔ نمونهٔ `/` آماده‌اند.
- `npm run lint`، `npm run typecheck`، `npm run test` و `npm run build`: همگی موفق؛ دو فایل تست و ۲۸ تست پاس شدند.
- مرورگر واقعی: زبان فارسی، جهت RTL و بارگذاری وزیرمتن تأیید شد؛ حالت روشن و تاریک در عرض ۳۶۰ پیکسل و نمایش دسکتاپ در عرض ۱۲۸۰ پیکسل بدون اسکرول افقی بودند.
- بازنشانی ورودی نمونه، برچسب ورودی و حالت غیرفعال دکمه بررسی شدند؛ خطای JavaScript مشاهده نشد.
- شرط Done مرحلهٔ دوم برقرار است. مرحلهٔ سوم شروع نشده و AGENTS.md و docs/SPEC.md تغییر نکرده‌اند.

## گزارش بررسی مرحلهٔ سوم

- اعتبارسنجی تنظیمات با Zod، اتصال کش‌شدهٔ Mongoose با `bufferCommands: false` و `maxPoolSize: 10`، نوع `ActionResult`، کلاس `AppError` و مسیر `/api/health` ساخته شدند.
- `npm run lint`، `npm run typecheck`، `npm run test` و `npm run build`: موفق؛ ۶ فایل تست و ۵۷ تست پاس شدند.
- بررسی HTTP واقعی روی برنامهٔ توسعه: با MongoDB روشن `db: "up"`، پس از توقف کانتینر `db: "down"` و بعد از روشن‌کردن مجدد، در همان برنامه `db: "up"` دریافت شد. volume و داده‌ها حفظ شدند.
- تست‌ها اشتراک اتصال بین درخواست‌های هم‌زمان و بارگذاری مجدد ماژول، تلاش مجدد پس از خطای اتصال، شکست ping، خطاهای تنظیمات و عدم افشای مقادیر حساس را پوشش می‌دهند.
- فایل محیطی محلی قدیمی فقط `MONGODB_URI` داشت؛ کلیدهای گمشده با حفظ مقدار موجود اضافه و یک `AUTH_SECRET` تصادفی تولید شد. فایل محیطی در Git نادیده گرفته می‌شود.
- شرط Done مرحلهٔ سوم برقرار است؛ مرحلهٔ چهارم شروع نشده و اسناد AGENTS.md و docs/SPEC.md تغییر نکرده‌اند.
